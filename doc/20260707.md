# kwja-mlx 深入 Code Review 記錄

**日期**：2026-07-07  
**審查範圍**：`kwja_mlx/`、`tests/`、`pyproject.toml`、`requirements.txt`、`.gitignore`、開發文件  
**審查工具**：`ruff`、`flake8`、`mypy`、`git log`、`python3 -m py_compile`

## 0. 整體結論

`kwja-mlx` 是架構清楚、功能完整的 KWJA Apple MLX 移植。char segmentation、word POS/NER、T5 reading/lemma/canon 分工明確，量化（quantization）後精度仍高。但專案仍處於「可運作但尚未工程化」階段：dependency 不一致、`.gitignore` 失效、docstring 與實作不符、dead code、型別註解不完整、缺少真正的單元測試。這些問題多數不影響正確性，但會增加長期維護成本。

**最優先處理**：dependency 同步、`.gitignore` 修正、移除 dead code、修正 docstring、補上基礎測試與 CI。

---

## 1. 架構與設計

### 1.1 模組切分

| 檔案 | 職責 | 評價 |
|------|------|------|
| `deberta_v2_mlx.py` | DeBERTa-v2 backbone | 完整，但 `p2c` 僅適用 query_len == key_len |
| `t5_mlx.py` | T5 encoder-decoder + greedy decode | 正確，但缺少 beam search / sampling |
| `extensions.py` | ConvLayer、TwoLayerClassifier | 存在 dead code，與實際使用版本不一致 |
| `analyzer.py` | 整合 pipeline、權重載入、CRF、量化 | 功能完整，但 batch POS/NER 未真正實作 |

### 1.2 設計疑慮

- **Analyzer docstring 順序錯誤**：`analyzer.py:1` 與 `analyzer.py:121` 寫 `char → seq2seq → word`，實際流程是 `segment()`（char）→ `tag()`（word）→ `read()`（seq2seq/T5），應為 `char → word → seq2seq`。
- **`tokenize_batch()` 名不符實**：函數名與 docstring 聲稱 batch POS/NER，但實際只對 segmentation batch，POS/NER 仍逐句呼叫 `self.tag(words)`（`analyzer.py:370-372`）。效能與文件皆需修正。
- **`extensions.py` 的 `ConvLayer` 是 dead code**：實際使用 `analyzer.py:66-73` 的 `ConvLayerMLX`（gelu activation）。`extensions.py:12-42` 的 `ConvLayer` 使用 tanh，完全未被引用，且 docstring 聲稱「matches HF ConvLayer: tanh」，與 BENCHMARK.md 記錄的「bug was gelu not tanh」矛盾，容易誤導。

## 2. 正確性與潛在 Bug

### 2.1 已確認正確

- **CRF Viterbi**：`_viterbi_decode()`（`analyzer.py:235-266`）正確使用 start/transition/end scores。
- **T5 scaling**：註解正確指出 T5 不使用 `1/√d_k`。
- **T5 KV cache**：self-attention 與 cross-attention 的 cache 邏輯正確。
- **DeBERTa mask**：`get_attention_mask()` 正確擴展為 `[B, 1, L, L]`。

### 2.2 需檢視區域

#### A. `DebertaV2Embeddings` 未傳入 attention_mask

`WordModule.__call__` 與 `CharModule.__call__` 在 inference 時都未傳 `attention_mask`，encoder 內部使用全 1 mask。單句無妨，但未來若要實作真正的 batch word tagging，必須傳入實際 mask，否則 padding 會影響 attention。

#### B. `T5ForConditionalGeneration.generate()` 回傳型別錯誤

`generate()` 標註 `-> mx.array`（`t5_mlx.py:281`），實際回傳 `list[int]`（`t5_mlx.py:308`）。建議改為 `-> list[int]`。

#### C. `read()` 對 SentencePiece `▁` 的過濾

`analyzer.py:416`：`tokens = [x for x in self.seq2seq_tok.tokenize(src_text) if x != '▁']`。此為經驗性 hack，無註解說明，可能無聲改變含底線輸入。建議補充註解或改用正規 tokenizer 參數。

#### D. `p2c` attention 僅支援 query_len == key_len

`deberta_v2_mlx.py:297-315` 的 `p2c` 分支在 query/key 長度不同時會 shape mismatch。目前僅用於 self-attention，不會觸發，但建議加上 assert 或補正。

#### E. `tag()` 中 `first_idx` 型別語意不清

`analyzer.py:387`：`first_idx = [None] * len(words)`，後續賦值 int。建議初始化為 `[-1] * len(words)`，並在最後 assert 無 `-1` 殘留。

## 3. 效能

- **優勢**：MLX quantization 顯著降低記憶體並提速；`segment_batch()` 已正確 padding。
- **瓶頸**：
  - `tokenize_batch()` 未真正 batch word tagging，產生多次 MLX eval overhead。
  - `segment()` / `segment_batch()` 頻繁 `mx.eval()` 並轉 numpy，batch 場景可考慮 vectorized decode。
  - `read()` 一次一句，未來可考 batch T5 decoding。

## 7. 測試

- `tests/test_wikipedia_japan.py` 是整合 benchmark 腳本，非 pytest 單元測試，無 assert。
- 依賴網路下載權重，執行時間長；硬編碼 `/tmp/wiki_japan_sents.txt`。

**建議補充的單元測試（無需權重）**：

- `_viterbi_decode()`：固定 emission/transition，驗證最短路徑。
- `Morpheme` / `AnalysisResult`：`to_text()`、`__repr__`。
- `ConvLayerMLX` / `TwoLayerClassifier`：forward shape。
- `T5RelativePositionBias._relative_position_bucket()`：與 HF T5 比對。
- `DebertaV2Embeddings`：output shape、mask 行為。
- 空輸入：`segment('')`、`tag([])`、`analyze('')` 回傳空集合。

**建議**：將 benchmark 腳本移至 `scripts/benchmark_wikipedia.py`，`tests/` 回歸純測試。

## 8. 安全性

- **模型下載無 checksum 驗證**：`hf_hub_download` 僅依賴 etag/caching。建議文件說明風險或加入 SHA256 檢查。
- **輸入長度**：`max_length=512` 僅截斷，超長輸入仍可能耗盡記憶體。文件應加建議。
- **測試使用 `/tmp/...`**：不具可攜性，且有被替換風險。
